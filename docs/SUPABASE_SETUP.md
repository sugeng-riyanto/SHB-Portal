# Supabase staging — persiapan awal

Status: contoh konfigurasi dan SQL hardening disiapkan, belum dijalankan, belum teruji terhadap PostgreSQL/Supabase. Ini bukan integrasi Auth atau RLS per peran dan bukan sistem siap produksi. Data API tidak diberi akses ke tabel SHB. Backend Django direct PostgreSQL tetap wajib menegakkan izin, karena koneksi berprivilege dapat melewati RLS. Gunakan proyek staging khusus, tidak berbagi database dengan ScanGrade atau aplikasi lain tanpa review.

1. Tentukan proyek Supabase khusus SHB Portal. Berikan nama/referensi proyek saja; jangan kirim database password, private key, service-role key, token, atau .env ke chat.
2. Simpan variabel sebenarnya di server secara aman dari `.env.example`: `POSTGRES_HOST`, `POSTGRES_PORT`, `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `DJANGO_SECRET_KEY`, dan `DJANGO_ALLOWED_HOSTS`. Kode saat ini membaca environment, bukan otomatis membaca file `.env`; environment harus dimuat oleh sistem deployment. SSL diwajibkan saat POSTGRES_HOST dipakai. Gunakan konfigurasi dan pengguna database yang sesuai rekomendasi Supabase dan kebutuhan migrasi; hak owner untuk migrasi dan hak runtime harus dipisahkan ketika dirancang.
3. Setelah project staging diidentifikasi dan backup/akses diverifikasi, uji migrasi Django pada database terisolasi: `python manage.py migrate`. SQL `deploy/supabase_hardening.sql` merujuk tabel yang dibuat migrasi Django, bukan membuat skema terpisah. Jalankan setelah migrasi dan review; skrip menolak bila tabel belum lengkap, mengaktifkan RLS, dan mencabut akses Data API dari `PUBLIC`, `anon`, `authenticated` untuk tabel yang disebutkan. Semua perubahan dalam satu transaksi.
4. Verifikasi pada staging: tabel ada; RLS aktif; Data API anon/authenticated tidak dapat membaca/menulis seluruh tabel; koneksi Django berjalan dan tes isolasi antarrole serta tenant lulus. Jangan mengekspos data ke API dengan mengaktifkan grants sampai kebijakan RLS per baris yang lengkap dan teruji tersedia. Tinjau juga default privileges dan setiap tabel baru yang ditambah migrasi. Dokumentasikan siapa pemilik tabel dan apakah runtime melewati RLS.
5. Supabase Auth, undangan, reset password, storage privat, webhook dan pengujian RLS autentikasi belum diimplementasikan. Django saat ini memakai auth bawaan untuk development. Jangan jalankan pada data murid nyata atau deploy publik.
