# Pengujian

Belum ada implementasi atau perintah tes final. Saat dibuat, dokumentasikan perintah dan versi lingkungan yang benar. Gunakan data sintetis. Unit: uang integer, pembulatan, tanggal, status dan denda. Integration: constraint, transaksi, impor campuran dan rollback, idempotensi, konflik, penyesuaian dan pembayaran sebagian. Security: akses silang peran, IDOR API, RLS dengan token nyata tiap peran, bypass privileged backend, pengumuman, login/reset/expiry, CSRF dan rate limiting. E2E: undangan → aktivasi → login → melihat anak dan tagihan; impor preview → konfirmasi → antrean email; email gagal/retry; kenaikan/lulus dan riwayat. SMTP staging menggunakan inbox pengujian, tidak kirim ke wali sungguhan. Verifikasi responsif ponsel/tablet/desktop, keyboard, label, kontras dan tabel alternatif grafik. Tes backup dan restore di lingkungan terisolasi. Sertakan hasil, versi, jumlah dan alasan skip; tidak menyebut PASS bila tes penting gagal atau tidak dijalankan.

Tambahan: uji kepala sekolah CRUD rekening dalam scope; tolak perubahan oleh peran tak berhak; nonaktifkan tanpa menghapus histori. Impor VA/nomor rekening berawalan nol, rekening tak dikenal/nonaktif, VA kosong, dan konflik; perubahan master tidak mengubah snapshot tagihan terdahulu. Uji satu wali dua anak lintas kelas dan wali lain tanpa hubungan; akses tagihan/VA lintas anak ditolak, undangan akun deduplikasi diverifikasi secara manual.

Uji clipboard VA dan fallback; wali dua anak, isolasi foto dan data lintas keluarga, kelas dan sekolah. Uji upload file valid/tidak valid/terlalu besar, preview private, isi nominal/tanggal, perubahan dan penarikan sebelum verifikasi, larangan perubahan setelah verifikasi, audit koreksi, admin verifikasi dan tolak, pencegahan double verification dan saldo tetap sampai diverifikasi. Wali kelas/kepala sekolah dapat preview sesuai penugasan; pihak lain ditolak.

Uji alert menjelang dan melewati jatuh tempo, pembayaran sebelum pengiriman, tanggal dan zona waktu, serta isolasi scope tiap role; uji tombol bantuan pada semua halaman dan lebar layar, akses keyboard, nomor belum diatur dan pembukaan nomor terverifikasi tanpa data sensitif. Pastikan seluruh hak pada matriks berlaku juga pada API dan private storage.

Uji perubahan pengaturan hanya oleh admin sesuai scope, validasi nomor dan jadwal, fallback logo, file logo tak valid, tampilan logo pada light/dark dan mobile, serta audit perubahan. Uji alert terhadap konfigurasi terkini dan tagihan yang telah lunas.
