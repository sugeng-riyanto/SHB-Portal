# Keamanan

RBAC + cakupan sekolah/jenjang/kelas/hubungan wali-anak ditegakkan pada backend setiap request dan pada RLS jika tabel diakses melalui Supabase Data API. Jangan percaya ID dari browser. Deny by default; uji lintas wali, lintas kelas dan manipulasi ID. Admin dibatasi cakupan penugasan. Akun nonaktif dan relasi dicabut langsung kehilangan akses. User metadata yang dapat diedit pengguna bukan sumber otoritas role. Jangan gunakan service-role key di browser; jika backend mem-bypass RLS, terapkan pemeriksaan identitas dan izin eksplisit.

HTTPS, cookie aman HttpOnly/Secure/SameSite jika memakai sesi, CSRF protection, rate limit login/reset/import, lockout adaptif, audit dan opsi MFA untuk staf. Sesuaikan mekanisme session/token dengan Auth setelah prototipe. Secrets melalui secret manager/env pada server; jangan commit, tampilkan dalam screenshot atau log. Gunakan Gmail app password atau OAuth sesuai dukungan akun, verifikasi pengaturan resmi; hindari kata sandi akun utama. Tautan satu kali dan expiry mengikuti konfigurasi Auth. Redaksi reset tidak mengungkap akun. Audit siapa, aksi, entitas, waktu, hasil dan correlation ID tanpa isi pesan, token atau data sensitif yang tidak perlu.

Akses file impor dibatasi, bersifat sementara dengan masa simpan ditetapkan; validasi ukuran/tipe dan isi, jangan jalankan formula, sanitasi ekspor. Perlindungan data anak: minimalkan data, kontrol ekspor dan akses, tetapkan masa retensi dan prosedur penghapusan berdasarkan kewajiban sekolah/hukum; kebijakan perlu ditinjau penanggung jawab. Ancaman utama: akses lintas keluarga, salah alamat email, kredensial bocor, duplikasi tagihan, manipulasi pembayaran, reset destruktif dan penyalahgunaan akun staf.
